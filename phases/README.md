# Phase files

Each `phase-N.md` (for N in 0..10) contains the wizard's logic for one phase: which questions to ask, scan-driven options to build, post-question actions to take.

The wizard's engine (`../META_PROMPT.md`) reads these on demand — one per phase, in order. This keeps the per-phase context window small.

## Conventions per file

```markdown
## PHASE N — <name>

Goal: <one sentence>

### Q<N.X> — <short title>
<setup + tier conditions + scan-driven option building + post-question action>
```

## Editing

- Question wording → `../wizard-questions.yaml` (the `text:` or `text_template:` field of the matching `id: q<N>_<X>` entry).
- Phase orchestration → this file (which questions run when, what scans precede them, how to handle edge cases).
- Variables generated by a phase → must be declared in `META_PROMPT.md`'s VARIABLES SCHEMA so they're rendered correctly in Phase 10.

After editing any phase file, run `bash validate.sh` from the repo root — the self-test catches template rendering failures, undeclared variables, and stale cross-references.
